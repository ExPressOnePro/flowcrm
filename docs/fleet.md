# Автопарк (Fleet) — техническая документация

Статус: этапы 2–3 (реестр ТС, сцепки, пробег, статусы, филиалы, роли),
мобильная основа (см. [mobile.md](mobile.md)), этап 4 — документы и напоминания,
этап 5 — водители и путевые листы.
Следующие этапы: 6 — лента операций, 7 — ТО, 8 — аналитика.

## Таблицы

| Таблица | Назначение |
|---|---|
| `branches` | Филиалы. Не удаляются, только деактивируются (`is_active`). |
| `organization_user.branch_id` | Филиал сотрудника в организации — основа ограничения доступа. |
| `vehicle_types` | Настраиваемые типы ТС: `can_tow` (буксирует), `is_towable` (прицеп), `has_odometer`. |
| `vehicles` | Реестр ТС. Soft delete = архив. `current_odometer_km` — кеш последнего показания. |
| `vehicle_couplings` | Сцепки тягач ↔ прицеп с периодом `coupled_at` … `uncoupled_at` (NULL = действует). |
| `vehicle_status_changes` | Журнал смен статуса (только добавление). |
| `odometer_readings` | Показания одометра (только добавление) с источником `source`. |

Все таблицы содержат `organization_id`; модели используют `BelongsToOrganization`.
Время хранится в UTC; ввод `datetime-local` интерпретируется в часовом поясе
организации (`App\Support\OrganizationTime`), вывод — тоже (`resources/js/lib/format.ts`).

## Бизнес-правила (`app/Actions/Fleet`)

- **RegisterVehicle** — создаёт ТС, первую запись в журнале статусов и (если указан)
  начальный пробег с источником `initial`.
- **Госномер** нормализуется (верхний регистр, одиночные пробелы) и уникален среди
  действующих (не списанных и не в архиве) ТС организации; сравнение игнорирует
  пробелы и дефисы. **VIN** — 17 символов без I/O/Q, уникален в организации.
- **ChangeVehicleStatus** — статус меняется только через это действие и всегда
  пишется в журнал. Списание требует причину и закрывает активные сцепки.
  Статус отражает учётное состояние, а не юридический допуск к эксплуатации.
- **CoupleTrailer** — тягач должен иметь тип с `can_tow`, прицеп — с `is_towable`;
  списанные ТС не сцепляются; периоды одного прицепа не пересекаются; позиция
  (1–3) на тягаче не занята.
- **UncoupleTrailer** — дата расцепки ≥ даты сцепки и не в будущем.
- **RecordOdometerReading** — показания монотонны во времени: не меньше любого
  более раннего и не больше любого более позднего. Для типов без одометра
  (прицепы) запись запрещена — их пробег будет вычисляться по периодам сцепок.
  Источник `telematics` зарезервирован для данных устройств и в UI помечается
  отдельно; вручную он не выставляется. Повторная отправка той же формы
  (то же ТС, значение, источник и автор в течение 60 секунд) возвращает уже
  созданное показание вместо дубля.
- **Архив** — запрещён при активной сцепке; история сохраняется; восстановление
  проверяет конфликт госномера.
- Тип ТС нельзя перевести в другое поведение (`can_tow`/`is_towable`/`has_odometer`),
  пока он используется.

## Роли и права

Права: `vehicles.view|create|update|change_status|archive|couple`, `odometer.record`,
`fleet.view_all_branches`, `branches.manage`, `vehicle_types.manage`, `audit.view`,
`analytics.view` (коммерческая аналитика `/analytics`; главная `/dashboard` — сводка
по автопарку), `documents.view|create|update|archive|notify`, `document_types.manage`,
`drivers.view|manage`, `waybills.view|create|issue|close|cancel`.

| Роль | Кратко |
|---|---|
| Owner, Admin | Всё. |
| Fleet Manager | Весь автопарк, справочники, документы, водители, путевые листы, журнал изменений, задачи. |
| Dispatcher | Просмотр всех филиалов, статусы, сцепки, пробег; просмотр документов и водителей; путевые листы полностью. |
| Document Controller | Просмотр всех филиалов; документы и их типы, напоминания о сроках; справочник водителей; просмотр путевых листов. |
| Branch Employee | Только свой филиал: просмотр, ввод пробега, документы; путевые листы — создание, выдача, закрытие (без отмены). |
| Viewer | Только просмотр, включая документы, водителей, путевые листы и журнал изменений. |

Без `fleet.view_all_branches` пользователь видит только ТС своего филиала
(`App\Support\BranchAccess`); если филиал не назначен — не видит ничего.
Проверка выполняется и в списках (`Vehicle::visibleTo`), и в политике `VehiclePolicy`
для каждого объекта.

## Реестр и карточка ТС

`GET /vehicles` — серверная пагинация; фильтры `search` (госномер или VIN),
`status`, `category`, `type`, `branch`, `coupled` (`0`/`1`),
`attention=stale_odometer` (нет показаний дольше `Vehicle::STALE_ODOMETER_DAYS`),
`archived`; сортировка `sort` — `plate`, `odometer`, `commissioned` (с `-` по
убыванию, пустые значения в конце). Неизвестные значения игнорируются.

Карточка (`/vehicles/{id}`) грузит только шапку и обзор; история подгружается
отдельными JSON-запросами при открытии вкладки:

| Маршрут | Право | Ответ |
|---|---|---|
| `GET /vehicles/{id}/timeline?type=&period=&before=` | `view` на ТС | `{items, has_more, next_before}` — статусы, сцепки/расцепки, пробег (`App\Services\VehicleTimeline`), по 30 событий. `type`: `all`/`status`/`coupling`/`odometer`; `period`: `7d`/`30d`/`90d`/`365d`/`all`. |
| `GET /vehicles/{id}/activity?before_id=` | `viewAudit` | `{items, has_more, next_before_id}` — журнал изменений, по 30 записей. |

## Документы (этап 4)

Таблицы: `document_types` (справочник: `subject` — `vehicle`/`driver`, `has_expiry`,
`is_mandatory`, `vehicle_categories` — пусто значит «все категории»), `documents`
(полиморфная связь `documentable`, сейчас только ТС), `document_files`,
`document_alerts` (отметки об отправленных напоминаниях), `notifications`
(стандартная таблица Laravel + `organization_id`).

- Состояние вычисляется по дате, не хранится: `valid`, `expiring` (≤ 30 дней,
  `Document::EXPIRING_DAYS`), `expired`, `no_expiry`, `archived`. Даты считаются
  в часовом поясе организации.
- Удаления нет ни в маршрутах, ни в политике. Архивирование — с обязательной причиной;
  архивный документ только для чтения. «Продлить» создаёт новый документ, а старый
  уходит в архив со ссылкой `replaced_by_id`.
- Тип должен подходить категории ТС; у используемого типа нельзя сменить
  `has_expiry`, а `subject` после создания не меняется.
- Повторная отправка формы с тем же `idempotency_key` возвращает уже созданный документ.
- Файлы: диск `documents` (`storage/app/private/documents`, не публичный), имя —
  случайный UUID, расширение — по содержимому. Разрешены PDF, JPG, PNG, WEBP, HEIC
  до 10 МБ, до 10 файлов за раз. Скачивание только через
  `GET /documents/{id}/files/{file}` с проверкой прав и филиала, заголовки
  `Cache-Control: private, no-store` и `nosniff`.
- Реестр `GET /documents`: `state`, `type`, `branch`, `search` (госномер или номер
  документа), `sort` (`expires`, `-expires`, `plate`, `type`). Счётчики и фильтры
  «истекает»/«просрочен», KPI на главной и блок «Требует внимания» не учитывают
  списанные ТС. Вкладка в карточке ТС грузится через
  `GET /vehicles/{id}/documents` (`?archived=1` — архив) и показывает обязательные
  документы, которых нет.

### Напоминания о сроках

`php artisan documents:notify-expiring` (в планировщике — каждый час,
`withoutOverlapping`). Работает только после 07:00 по времени организации
(`--now` — без этой проверки). Пороги — 30, 14, 7, 1 день и «истёк»
(`DocumentAlert::THRESHOLDS`). Для каждого документа и порога в `document_alerts`
пишется одна строка с уникальным ключом, поэтому повторный запуск ничего не
отправляет. Если документ сразу попал в несколько порогов, уходит одно напоминание
о самом срочном. Изменение даты окончания сбрасывает отметки.

Получатели — активные участники с правом `documents.notify`, которым виден филиал ТС.
Каждый получает уведомление в приложении (колокольчик в шапке, `/notifications`)
и одно письмо-сводку за запуск. Нужны cron `* * * * * php artisan schedule:run`
и настроенный `MAIL_MAILER` (локально — `log`). Push-уведомлений нет.

## Водители и путевые листы (этап 5)

### Водители

Таблица `drivers`: ФИО, телефон, номер удостоверения, категории (`license_categories`),
срок удостоверения, филиал, необязательная связь с учётной записью (`user_id`,
один водитель на пользователя), статус `active`/`inactive`. Водителя нельзя удалить —
только деактивировать (у неактивного не учитываются документы в счётчиках сроков,
его нельзя выбрать в новом путевом листе). Документы водителя — те же `documents`
с `subject = driver` (медсправка, удостоверение и т. п.), с той же защитой файлов и
напоминаниями. Страницы: `/drivers` (поиск, статус, филиал), `/drivers/{id}`
(вкладки «Обзор», «Документы», «Путевые листы»).

### Путевые листы

Таблица `waybills`: ТС, прицеп (необязательно), водитель, филиал (по ТС), маршрут,
основание рейса (`basis` — заказ, договор, заявка), плановые выезд и возврат,
фактические выезд и возврат, показания одометра, топливо при выезде и возврате и
заправлено (`departure_fuel_l`, `return_fuel_l`, `fuel_added_l`, литры), примечания,
причина отмены. Статусы: `draft` → `issued` → `closed`; `draft`/`issued` → `cancelled`.

- **SaveWaybillDraft** — черновик без номера; повторная отправка с тем же
  `idempotency_key` возвращает уже созданный черновик. Редактировать можно только черновик.
- **IssueWaybill** — номер `ГГГГ-NNNNN` присваивается только при выдаче (отменённые
  черновики номер не занимают; при одновременной выдаче — повтор со следующим номером).
  Время выезда не в будущем. Показание одометра при выезде обязательно для ТС с
  одометром и записывается в историю пробега через `RecordOdometerReading`
  (источник `waybill_departure`, ссылка на путевой лист) — с теми же проверками
  монотонности.
- **CloseWaybill** — время возврата не раньше выезда и не в будущем; показание при
  возврате — источник `waybill_return`. Пробег за рейс считается **только** как
  разница двух показаний; если какого-то нет — пробег не вычисляется.
- **CancelWaybill** — с обязательной причиной; записанные показания одометра
  остаются в истории (история пробега не переписывается).

Проверки (`App\Services\WaybillChecks`) разделены по уровням:

| Уровень | Что | Поведение |
|---|---|---|
| Блокирует выдачу | ТС списано или в архиве; прицеп как основное ТС; ТС/прицеп/водитель уже в открытом путевом листе; тягач не может буксировать прицеп; водитель неактивен | Ошибка у поля, выдача невозможна |
| `danger` | Просроченные документы ТС, прицепа или водителя | Предупреждение, выдача разрешена |
| `warning` | Статус «в ремонте»/«простой»; нет обязательных документов; нет номера удостоверения; категории прав не включают обычно нужную (CE/C/D/B); пересечение по времени с другим путевым листом того же ТС, прицепа или водителя (±7 дней, без планового возврата — окно 12 ч) | Предупреждение |

Статус ТС и документы не считаются юридическим запретом — это предупреждения.
В интерфейсе дополнительно (без блокировки): показание при выезде больше последнего
записанного более чем на 3000 км, рейс длиннее 3000 км, топливо при возврате больше,
чем при выезде с учётом заправок.

Маршруты: `/waybills` (фильтры: статус, включая «возврат просрочен», поиск, филиал,
период; счётчики по статусам), `/waybills/create`, `/waybills/{id}`,
`/waybills/{id}/edit`, действия `POST /waybills/{id}/issue|close|cancel`; JSON-списки
`GET /vehicles/{id}/waybills` (как ТС и как прицеп) и `GET /drivers/{id}/waybills`.
Главная: KPI «В рейсе», «Возврат просрочен», «Закрыто сегодня» и блок «Последние
путевые листы» (сначала открытые). В истории ТС показания из путевого листа
ссылаются на него.

## Журнал изменений

Spatie Activity Log, лог `fleet`: изменения `vehicles`, `vehicle_couplings`,
`branches`, `vehicle_types`, `drivers`; лог `documents`: типы документов, документы,
файлы; лог `waybills`: путевые листы (включая основание и топливо).
Типы субъектов хранятся как алиасы morph map
(`vehicle`, `vehicle_coupling`, …), см. `AppServiceProvider::MORPH_MAP`.

## Команды

```bash
php artisan migrate               # без --fresh; данные сохраняются
php artisan roles:sync            # права, роли и справочники для всех организаций (идемпотентно)
php artisan db:seed --class=FleetDemoSeeder   # демо-автопарк (пропускается, если ТС уже есть)
php artisan db:seed --class=FleetDocumentsDemoSeeder   # демо-документы (пропускается, если документы уже есть)
php artisan db:seed --class=FleetWaybillsDemoSeeder    # демо-водители и путевые листы
php artisan documents:notify-expiring --now   # разослать напоминания сейчас
php artisan test tests/Feature/Fleet
```

Демо-пользователи (пароль `password`): `fleet@`, `dispatcher@`, `docs@`,
`branch@` (филиал Бельцы), `viewer@` — домен `flowcrm.test`.

## Локализация

Язык по умолчанию — русский (`APP_LOCALE=ru`). Серверные строки — `lang/ru.json`
и `lang/ru/*.php`; интерфейс — `resources/js/lang/ru.ts` (ключ = английский текст)
и `resources/js/lang/enums.ts` (подписи значений перечислений). Переведены страницы
автопарка, главная, аналитика, задачи и клиенты; остальные CRM-страницы и настройки
пока на английском.
